実行: `GEMINI_API_KEY=... npm run eval:models -- [--models a,b] [--runs 2] [--max-calls 300] [--delay-ms 500]`（`scripts/eval-models.ts`）。
**費用が出るので、1 回の実行で送る呼び出しは `--max-calls`（既定 300、再試行も数える）が上限。** 上限を超える組み合わせは 1 件も送らずに止まる。最初の 6 回がすべて失敗したモデルは打ち切る。

## 上位モデルを測れていない理由（人の作業）

いま `GEMINI_API_KEY` は無料枠のキーで、`gemini-3.5-flash`・`gemini-3.1-pro-preview` は 429（上限超過）、`gemini-3.8-flash` は 503（高負荷）だった。`gemini-2.5-flash` は新規ユーザーには提供終了（404）。

1. Google AI Studio で、このキーのプロジェクトに課金を有効にする（ダッシュボード操作）。
2. 有効にしたら、上位モデルだけを 1 回測る（現行の結果は再利用するので送らない）:
   `GEMINI_API_KEY=... npm run eval:models -- --models gemini-3.8-flash,gemini-3.5-flash --max-calls 140 --delay-ms 500`
   （2 モデル × 52 回 = 104 回。見込みの費用は 1 ドル未満）
3. 出た表を、この文書の表と `eval/model-results.json` に書き足す。

## 切り替える基準

次の**すべて**を満たすときだけ、`ESTIMATE_MODEL`（Edge Function の環境変数）を上位モデルに切り替える。

1. 正答率が現行より **5 ポイント以上** 高い（この評価セットでは 52 回中 3 回以上の差。2 回違うだけなら誤差とみなす）。
2. 1 回あたりの費用が現行の **4 倍以内**（現行 $0.00083 → $0.0033 まで。1 日の全体上限 `GLOBAL_DAILY_LIMIT` で最悪の月額を計算して許容できること）。
3. 平均の遅さが **5 秒以内**（入力中に待たされないこと）。
4. **初回の**失敗率（429・503・通信エラー。再試行で成功したものも数える。本番は再試行しないため）が **2% 以下**。`npm run eval:models` の「初回失敗率」列で見る。

切り替えは `supabase secrets set ESTIMATE_MODEL=...` だけで戻せる（コードの変更なし）。これは本番の変更なので、人が行う。

現時点の判断: 上位モデルが測れていないので **切り替えない**（現行のまま）。

注: 表の現行モデルの結果は、初回失敗率を記録する前の実行のもの（最終エラーは 2/52）。遅さも、`--delay-ms 500` の待ち（約 0.5 秒）を含んでいたので、実際はそのぶん短い。上位モデルを測る実行で、現行も含めて測り直すと基準を同じ条件で比べられるが、費用が出るので 1 回だけにする（現行を足しても 156 回）。
