> **ステータス：すべて「案」。** プライバシーポリシー・規約は健康データの共有に関わる重要な文面なので、このファイルの変更案は **`docs/privacy-policy.md` / `docs/terms.md` / `web/legal.html` にはまだ反映していない**。人間が最終確認（できれば法律の専門家の確認）をしたあとで反映する。

## 1. 栄養表示ラベル（App のプライバシー）回答案

v1.0 の表（`docs/app-store-listing.md` の「App のプライバシー」）に **足す・変える** もの。「トラッキング」は全項目いいえ（ATT 不要）。

| 種類 | 項目 | v1.1 での扱い | 使い道 | 紐づく |
|---|---|---|---|---|
| ヘルスケアとフィットネス | ヘルス（体重） | 既存。**コーチに共有される**（本人が承認・体重をオンにした場合のみ）。ヘルスケアから読み込んだ体重も、同じ体重として共有対象になる（体脂肪率は共有しない） | アプリの機能 | はい |
| ヘルスケアとフィットネス | フィットネス（トレーニング、食事の記録） | 既存。**コーチに共有される**（同上。トレーニングは種目・重量・回数、食事は栄養の合計と直近7日の食事名） | アプリの機能 | はい |
| ユーザコンテンツ | その他のユーザコンテンツ | 既存に **追加**：コーチが送る「ひとこと」とメニュー（コーチ側の利用者が入力） | アプリの機能 | はい |
| 連絡先情報 | 名前 | **追加**：コーチ名（コーチが入力）、生徒の名前（生徒が入力。共有時にコーチへ表示される） | アプリの機能 | はい |
| 診断 | クラッシュデータ | #4（Sentry）を入れたビルドから追加（`docs/release-checklist.md` D 参照）。v1.1 のビルドが Sentry を含むなら必ず入れる | アプリの機能 | いいえ |
| 使用状況データ | — | #23（計測）を有効にしないなら **追加しない** | — | — |

補足（回答時の考え方）：
- Apple の質問は「他の利用者に見せる」場合も「収集」に含まれる。コーチへの共有は、サーバー（Supabase）を経由するので、上の「紐づく：はい」で申告する。
- 「サードパーティに共有するか」の質問：コーチは**利用者の1人**で、Apple の言う第三者パートナー（広告・解析 SDK など）ではない。共有先の事業者（Supabase、Google Gemini、Sentry）は v1.0 から変わらない。迷ったら、v1.0 の回答を踏襲して「共有先はサービス提供のための委託」と考える。
- 年齢制限は 4+ のまま（医療情報の質問は「なし」。コーチ機能は他の利用者との交流だが、自由なチャットや投稿はなく、コーチ→生徒は短いひとこと（500字まで）のみ）。**ユーザ生成コンテンツ（UGC）の質問に「あり」と答えるかは、App Store Connect の質問文を読んで人間が判断**（§4 の確認事項）。

## 2. 審査メモ（App Review Information）の追加文

v1.0 の審査メモ（`docs/app-store-listing.md`）の末尾に、次を足す案。〔 〕は審査用アカウントを作ったあと（#31）に埋める。

```
【v1.1 追加：コーチ機能】
コーチ機能は任意です。設定 →「モード」→「コーチとして使う」をオンにした場合だけ、コーチ用の画面が出ます。オンにしない限り、画面・タブ・通知は増えず、何も共有されません。コーチ機能の利用には Sign in with Apple のログインが必要です。

[確認の手順]
1. コーチ役のアカウントでログイン → 設定 → モード →「コーチとして使う」→ コーチ名を入れる → 招待コード（6文字）が表示されます。
2. 生徒役のアカウントでログイン → 設定 →「コーチと共有」→ 招待コード〔審査用コード：記入〕を入れる → コーチ名が表示される → 共有する項目（食事・体重・トレーニング）を項目ごとに選び、本人が「承認」するまで、コーチには何も表示されません。
3. コーチ役の画面で、生徒の記録の要約、目標の設定、メニューの作成、ひとことの送信ができます。
4. 生徒役の画面で、「ひとりで」に切り替える（共有の一時停止）／「共有をやめる」（コーチ側の共有データを削除）ができます。
5. アカウント削除は、設定の一番下の「アカウントを削除」にあります。削除すると、コーチとのつながりと共有データもすべて削除されます。

[健康データの取り扱い]
・共有されるのは、本人が承認し、項目ごとにオンにしたデータだけです（食事・体重・トレーニングの直近約9週間。食事の写真・メモ・生年月日・性別・身長・体脂肪率は共有しません）。
・ヘルスケアから読み込んだ体重は、本人が「体重」の共有をオンにした場合に限り、コーチに表示されます。ヘルスケアのデータは、広告・解析・データ販売には使いません。
・共有相手は本人が承認したコーチ1人だけで、招待コードの入力を繰り返し間違えると一時的に止まります（総当たり対策）。
・コーチは本アプリの利用者の1人で、運営者の従業員ではありません。数値はすべて一般的な計算にもとづく目安で、医療的な助言ではありません。
・審査用アカウント（コーチ役：〔記入〕、生徒役：〔記入〕）を用意しました。
```

ログイン情報の入れ方（人間の判断）：このアプリは Sign in with Apple のみで、メール・パスワードの入力欄がない。コーチ役と生徒役の2人分が必要なので、案は2つ。
- 案A：「サインインが必要」をオンにし、こちらで用意した Apple ID 2つ（コーチ役・生徒役）の情報を書く。審査員は端末の Apple ID を切り替えるか、2台で確認する。
- 案B：「サインインが必要」はオフのまま、審査員が自分の Apple ID でコーチ役になり、生徒役は上の手順 2 に必要な招待コードを使って自分のもう1つの端末で確認してもらう（審査員の負担が大きく、通りにくい）。

#31 でアカウントを作るときに、案Aで進めるのを推奨する。

## 3. 規約・ポリシーの変更案（差分案）

### 3-1. プライバシーポリシー（`docs/privacy-policy.md`、同じ内容を `web/legal.html` にも反映）

**(a) §1「取得する情報」の表：コーチとの共有の行を差し替える案**

```diff
-| コーチとの共有（任意） | 「コーチと共有」を**自分で承認した場合だけ**、自分が選んだ項目（食事・体重・トレーニング）の直近約2か月分。コーチが送った目標・メニュー・ひとこと | クラウド（Supabase）。共有相手のコーチだけが読めます |
-| コーチとして使う場合（任意） | コーチ名、招待コード、生徒の名前（生徒が入力したもの）と共有された記録、作ったメニュー、送った目標とひとこと | クラウド（Supabase） |
+| コーチとの共有（任意） | 「コーチと共有」を**自分で承認した場合だけ**、自分が選んだ項目の直近約9週間分（食事：日ごとの合計と、直近7日の食事名・栄養／体重：日ごとの体重（kg）／トレーニング：種目・重量・回数）。あわせて、項目の選択にかかわらず、**目標に関する情報**（目標の種類、目標体重、ペース、たんぱく質の目安、推定消費カロリー、1週間の予定）と、自分が入力した**名前**をコーチに表示します。コーチが送った目標・メニュー・ひとこと | クラウド（Supabase）。共有相手のコーチだけが読めます |
+| コーチとして使う場合（任意） | コーチ名、招待コード、生徒の名前（生徒が入力したもの）と、共有された記録、作ったメニュー、送った目標とひとこと | クラウド（Supabase） |
```

**(b) §1-2「コーチとの共有について」：箇条書きの変更案**

```diff
 - 見せる項目（食事・体重・トレーニング）は、項目ごとにオン／オフできます。オフにした項目は、コーチには「非公開」とだけ表示されます。
-- **写真、メモ、生年月日などのプロフィールは、共有しません。**
+- 項目のオン／オフとは別に、コーチに見えるものがあります：自分が入力した名前、目標の種類・目標体重・ペース・たんぱく質の目安・推定消費カロリー（TDEE）・1週間のトレーニングの予定。
+- **食事の写真、メモ、体脂肪率、生年月日・性別・身長は、共有しません。**
+- 体重の共有をオンにしている場合は、ヘルスケアから読み込んだ体重も、ほかの体重と同じようにコーチに表示されます。ヘルスケアのデータは、広告・解析・販売には使いません。
-- 共有はいつでもやめられます（設定 → コーチ → 共有をやめる）。やめると、コーチからは見えなくなり、コーチ側に置いた共有データも削除されます。「ひとりで」に切り替えると、共有を一時停止できます。
+- 共有はいつでもやめられます（設定 → コーチ → 共有をやめる）。やめると、コーチからは見えなくなり、コーチ側に置いた共有データも削除されます。「ひとりで」に切り替えると、共有を一時停止できます（一時停止中は、コーチには何も表示されず、新しい記録も送られません。ただし、最後に送った共有データは、再開または共有をやめるまで、当方のサーバーに残ります）。
+- コーチが送った目標・ひとことの記録は、共有をやめた後もサーバーに残り、アカウントを削除すると消えます。
```

**(c) §3「第三者への提供・委託」** は変更なし（コーチは第三者委託先ではなく、本人の承認で情報を見る利用者の1人。現行の「コーチは…利用者の1人です」の項で足りる）。
**(d) §7「変更」** ：v1.1 公開時に「最終更新日」を更新。

### 3-2. 利用規約（`docs/terms.md`、同じ内容を `web/legal.html` にも反映）

**§2-2「コーチ機能について」に足す案**

```diff
 - コーチとして使う方は、生徒から共有された情報を、指導の目的のためだけに使い、他人に見せたり、公開したりしてはいけません。生徒の同意のない共有の依頼（招待コードの不正な入手や、総当たりなど）を禁止します。

+- コーチとして使う方は、診断・治療などの医療行為にあたる助言をしてはいけません。
+- 招待コードは、共有したい相手にだけ伝えてください。不特定多数に公開してはいけません（コードは設定でいつでも作り直せます）。
```

## 5. 確認した事実（コードと SQL から）

| 事項 | 確認したこと | 根拠 |
|---|---|---|
| 共有の範囲（期間） | 直近 **9 週間（63日）**。食事の直近の一覧は直近 **7日**。トレーニングは最大 **60 回** | `snapshot.ts` の `SNAPSHOT_WEEKS = 9`、`recentFrom`、`.slice(-60)` |
| 項目ごとの共有 | 食事・体重・トレーニングは、オフにすると `snap.meals/weight/training` が作られず、サーバー側でも外して返す | `snapshot.ts`、`coach_students()` |
| **常に共有される項目** | `profile`（目標の種類、目標体重、ペース、たんぱく質、脂質%、TDEE、週のカロリー、係数、週の予定、管理中か）は、項目のオン／オフに関係なく共有される。生徒の名前も常に見える | `snapshot.ts` の `profile`、`coach_links.student_name` → 現行ポリシーの「選んだ項目だけ」と不一致 → §3-1 で開示 |
| 共有しないもの | 写真、メモ、体脂肪率（体重は kg だけ）、生年月日・性別・身長・年齢（TDEE の結果は共有される） | `snapshot.ts` |
| ヘルスケアの体重 | HealthKit から読んだ体重は `weights` に入り、体重共有がオンならコーチに表示される | `src/app/_layout.tsx`（`setWeight(..., source: 'healthkit')`） → 審査メモで明示 |
| 承認前は何も見えない | 招待コード入力 → 承認で `coach_links` が作られる。`coach_shares` は本人しか書けず、コーチは `coach_students()`（有効な接続先のみ）経由 | SQL の RLS ポリシー |
| 一時停止 | `paused` の間はコーチに `payload = null`。ただし `coach_shares` の行はサーバーに残る（削除されない） | `coach_students()`、`update_my_link()` → §3-1(b) で開示 |
| 共有をやめる | `revoke_my_link()` が `coach_shares` を削除する。`goal_plans` / `coach_notes` は残る（コーチが送った内容） | SQL |
| アカウント削除 | `auth.users` の削除で、`coaches`・`coach_links`・`coach_shares`・`goal_plans`・`coach_notes`・`invite_attempts` が `on delete cascade` で消える。写真（Storage）は関数で先に消す | SQL、`delete-account/index.ts` |
| 総当たり対策 | 1時間に失敗10回で止まる。1人のコーチにつながれる生徒は100人まで。生徒が同時につなげるコーチは1人 | `preview_invite()` |
| 通知 | コーチ機能のためのプッシュ通知はない（通知は端末内のローカル通知2種類のみ）。#33 で追加するなら、ここと審査メモを見直す | `src/services/notifications.ts` |
| v1.0 の表との差 | `app-store-listing.md` は「診断：収集しない」だが、#4（Sentry）が main に入っている。Sentry を含むビルドなら「クラッシュデータ」を足す必要がある | `docs/release-checklist.md` D、`docs/app-store-listing.md` |
