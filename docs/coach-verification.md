# コーチ機能の実機検証と審査用アカウント（#29・#31）

v1.1 でコーチ機能を出す前の、人間の作業の手順書。審査メモの文面は `docs/v1.1-review-prep.md`、アカウントの入れ方の案もそこにある。

## 0. 前提（確認済み）
- 本番の Supabase に、コーチ機能の 6 テーブル（`coaches`・`coach_links`・`coach_shares`・`goal_plans`・`coach_notes`・`invite_attempts`）と RPC 4 つ（`preview_invite`・`coach_students`・`revoke_my_link`・`update_my_link`）が**すでにある**（2026-10-08 に確認）。マイグレーションの追加適用は不要。
- 本番の `coaches` と `coach_links` は 0 件。利用者はまだいない。
- 本番ビルド（v1.0）には `EXPO_PUBLIC_COACH_MODE` がない。コーチ機能の入口は出ていない。
- コーチ機能の利用には **Sign in with Apple** が必要（メール・パスワードの入力欄はない）。

## 1. 審査用アカウントを 2 つ用意する（#31）

審査員が 1 つの端末でコーチ役と生徒役の両方を試せるよう、Apple ID を 2 つ用意する（`docs/v1.1-review-prep.md` の案 A）。

1. **Apple ID を 2 つ作る**（または、すでにあるテスト用を使う）。
   - 例: コーチ役 `plate.review.coach@…`、生徒役 `plate.review.student@…`。
   - 受信できるメールアドレスで作る。2 段階認証は、審査員が使えるよう、**信頼できる電話番号を手元に置く**か、App Store Connect の審査メモに手順を書く。
2. 実機でそれぞれの Apple ID で PLATE にログインし、**ログインが通ること**を確認する（App Store 版のビルドでは Sign in with Apple のみ）。
3. コーチ役のアカウントで、設定 → モード →「コーチとして使う」をオン → コーチ名を入れる → **招待コード（6 文字）を控える**。
4. 審査メモ（`docs/v1.1-review-prep.md` §2）の〔 〕を埋める。
   - コーチ役: Apple ID とパスワード
   - 生徒役: Apple ID とパスワード
   - 招待コード
5. App Store Connect の「サインインが必要」をオンにして、同じ情報を入力する。

注意:
- 審査用アカウントのパスワードは、**リポジトリに書かない**。App Store Connect にだけ入れる。
- 審査が終わったら、審査用アカウントの共有を解除し、不要なら削除する（設定の一番下「アカウントを削除」）。

## 2. 2 台の実機で検証する（#29）

### 2-1. 準備
- 実機 2 台（または 1 台＋シミュレーターは不可。Apple ログインと HealthKit のため実機）。
- 開発ビルドを作る。

  ```
  # .env.local に EXPO_PUBLIC_COACH_MODE=1 を入れておく
  npx eas-cli@latest build --profile development --platform ios
  ```

  EAS の development プロファイルの環境変数にも `EXPO_PUBLIC_COACH_MODE=1` が必要な場合は、登録するか、`npx expo run:ios --device` で手元からビルドする。
- 開発ビルドなら、コーチが決めた目標の**翌日反映**を、開発専用のスイッチ（#35）で当日にできる。
- 2 台に同じビルドを入れ、それぞれ別の Apple ID でログインする（1 で作った 2 つを使うと、そのまま審査の予行にもなる）。

### 2-2. 確認項目

| # | 台 | 手順 | 期待 |
|---|---|---|---|
| 1 | コーチ | 設定 → モード →「コーチとして使う」をオン → コーチ名を入力 | 招待コードが表示される |
| 2 | 生徒 | 設定 →「コーチと共有」→ 招待コードを入力 | コーチ名が表示される。**承認するまで、コーチ側には何も出ない** |
| 3 | 生徒 | 共有する項目（食事・体重・トレーニング）を選び、承認 | コーチ側に生徒が現れる |
| 4 | コーチ | 生徒の記録の要約を見る | 選んだ項目だけ表示。写真・メモ・体脂肪率・生年月日は出ない |
| 5 | コーチ | 目標を設定（ペースを選ぶ） | ペースが**体重の %** の範囲から選べる。範囲を超える値で警告が出る。1 日 1,200kcal 未満でも警告 |
| 6 | 生徒 | 目標の反映を確認 | 通常は翌日 0 時から。開発スイッチで当日反映 |
| 7 | コーチ | メニューを作る／ひとことを送る | 生徒側に届く |
| 8 | 生徒 | 設定で「ひとりで」に切り替え | 共有が止まり、コーチ側のデータが非表示。自分の目標に戻る |
| 9 | 生徒 | 「コーチと」に戻す | 共有が再開される |
| 10 | 生徒 | 「共有をやめる」 | コーチ側の共有データが削除される |
| 11 | 生徒 | 招待コードを何度も間違える | 1 時間に 10 回失敗で一時的に止まる |
| 12 | 生徒 | アカウント削除 | コーチとのつながりと共有データがすべて消える |
| 13 | 両方 | 機内モード | 同期はあとで再開。アプリは普通に動く |
| 14 | コーチ | 体重が軽い生徒（例: 45kg）で目標を設定 | 選べるペースが小さな値になり、速すぎる値は警告 |

### 2-3. 見つけた不具合
- 再現手順と画面を、issue（`coach` ラベル）にする。
- 確認が済んだら、#29 にチェックを入れて閉じる。

## 3. 検証の後
1. `docs/v1.1-review-prep.md` §4 の残りを済ませる（ポリシーの確認、App Store Connect の入力）。
2. `version` を上げ、EAS の production に `EXPO_PUBLIC_COACH_MODE=1` を登録して、ビルド・提出。
3. v1.1 を出したら、#29・#31・#32 を閉じ、#41 のチェックを付ける。
