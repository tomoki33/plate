# v1.1 リリースノート（下書き）

基準: v1.0 提出時点（`189c6ec`）から `main` 先頭までの変更。**計測（#23）・push 通知（#33）・英語対応（#39）は入れない。Sentry（#4）はコードだけ入り、DSN 未登録なので動かない。**

## 1. App Store「このバージョンの新機能」（案・日本語）

```
・ペースの選び方がわかりやすくなりました。選択肢に「体重の何％／週か」と「ゆっくり／ふつう／速い」を表示します。
・同じ食品を記録するとき、前回の量を初期値にします。入力の手間が減ります（記録は端末の中だけで使います）。
・写真の食事推定を、より速く、安定して使えるようにしました。送る前に写真を縮小します。
・食事名から食品を選ぶ精度を改善しました（「タンドリーチキン」のような料理が材料に誤って当たる例を減らしました）。
・バックアップからの復元を、より安全にしました。壊れたデータでは復元せず、今のデータを守ります。
・コーチ機能を追加しました（任意）。設定 → モードから、コーチとして使うか、コーチに記録を共有するかを選べます。オンにしない限り、画面は増えません。共有する項目は選べて、いつでもやめられます。
・そのほか、不具合の修正と安定性の改善。
```

※ コーチ機能の行は、`EXPO_PUBLIC_COACH_MODE=1` を登録して出す場合だけ入れる。

## 2. GitHub Release ノート（案）

### 利用者に見える変更
- ペースの選択肢に体重比（%/週）と速さの一言、注記を表示（#20）
- 同じ食品の量を、前回の量から始める。AI 推定・検索・マイセットに反映。端末内のみ（#13）
- 写真を送る前に長辺 1280px へ縮小（#15）。**ネイティブモジュール `expo-image-manipulator` を追加**
- AI の指示文を見直し、カタログへの過剰一致を減らす（#16）。サーバー側（反映済み）
- 復元の安全性を向上。表の形が壊れたバックアップでは、既存データを消さずに失敗として扱う（#3、#44、#52）
- 全角の数字で書いた量（例: 米１５０ｇ）を、前回の量で上書きしない（#47、#54）
- コーチ機能のペース選択と警告を、体重の % に合わせる（#30）。**コーチモード（`EXPO_PUBLIC_COACH_MODE=1`）のビルドのみ**

### サーバー・運用（アプリのバージョンとは別に、すでに反映済みのもの）
- 写真 AI の全体 1 日上限 3,000 回。確認に失敗したときは通さず 503（#2、#43、#49）
- Supabase の keep-alive（2 日おき）で、無料枠の自動停止を防止（#1）

### 開発・品質
- CI（型チェック・lint・テスト・`coach/` の型チェック・本番バンドルの検査）（#8、#24）
- 評価ハーネス `npm run eval:foods`、`eval:prompt`、`eval:models`、`backtest:tdee`（#11、#16、#17、#19）
- 復元・ストア・コーチ状態のテスト追加（#3、#9）
- lint の警告を解消（#27）
- Supabase マイグレーションを `db push` 運用に移す手順（#26）
- クラッシュ監視 Sentry を導入（DSN 未登録で無効）（#4）
- 開発ビルド専用の「翌日反映を今日にする」スイッチ（#35）

### ドキュメント
- 審査準備（#32）、push 通知の設計案（#33）、有料化の線引き案（#36）、英語対応の判断材料（#39）、メンテナンスのチェックリスト（#40）、ログインなしの写真 AI の改善案（#21）

## 3. 出す前の動作確認（実機）

| 確認 | 手順 | 期待 |
|---|---|---|
| 量の個人化（#13） | 食品を検索 → 量を変えて記録 → もう一度同じ食品を選ぶ | 前回の量が初期値。確認画面に「前回の量」の表示 |
| 文章で量を書いた場合 | 「米150g」など、量を書いて AI 推定 | 書いた量が優先され、前回の量で上書きされない（全角も） |
| ペース表示（#20） | 初回設定／設定のペース選択 | 各選択肢に % と「ゆっくり／ふつう／速い」。折り返しや読みやすさに問題なし |
| 写真の縮小（#15） | 大きな写真（カメラで撮影）で AI 推定 | 413 にならず推定できる。速度が落ちない |
| 復元（#44、#52） | バックアップ → 復元（置き換え） | 元どおり戻る。壊れたバックアップを復元しようとしても、データが消えない |
| 食品の当たり方（#16） | 「タンドリーチキン」「唐揚げ」など | 料理が材料に誤って当たらない（唐揚げは唐揚げ） |
| ログインなしの利用 | ログインせずに記録 | これまでどおり使える |
| 本番ビルド（#24） | 本番ビルドのバンドル検査 | コーチ機能の文字が出ない（COACH_MODE なしの場合） |
| コーチ機能（#29） | 開発ビルド 2 台で招待・共有・ペースの警告 | `docs/v1.1-review-prep.md` の手順 |

## 4. 出し方の注意
- `app.json` の `version` を上げる（例 `1.1.0`）。`runtimeVersion` が `appVersion` ポリシーなので、旧ビルド（1.0.0）には OTA が届かない。#15 のネイティブモジュールがあるため、これが必須。
- ビルド前に確認: `supabase functions list` で `estimate-meal` が最新（10/6 07:28 以降）であること。
- コーチ機能を入れるなら EAS production に `EXPO_PUBLIC_COACH_MODE=1` を登録。入れないなら登録しない。
